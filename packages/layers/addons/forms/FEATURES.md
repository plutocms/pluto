# Features of @plutocms/forms

- Forms for any site, built from blocks in the admin (the `form` content type with the field blocks `form-input`, `form-textarea`, `form-select`, `form-radio`, `form-checkbox`, `form-consent`, `form-hidden` and `form-submit`) or defined in code (`definePlutoForm`); `<PlutoForm>` and the `::pluto-form` block draw a form with accessible plain CSS markup, `usePlutoForm` is the headless version, the field components are overridable by name, and `definePlutoFormField` adds a field type; one pure validation runs in the browser and on the server: @../../../../.claude/skills/forms/SKILL.md
- `POST /api/pluto/v1/forms/<handle>/submissions` with spam protection (a honeypot, a minimum fill time from a signed token, a rate limit for each IP, optional Cloudflare Turnstile), the Nitro hooks `pluto:forms:before-store` and `pluto:forms:submission`, an email to the recipients, and a store that is never the Git repository (a Nitro storage mount, a development folder, or a store that a backend layer registers); a daily task deletes old submissions; the public API never shows the recipients: @../../../../.claude/skills/forms/SKILL.md
- Admin pages for the submissions of each form (a table with paging, a detail view, delete, a CSV export that guards against formulas) and a setup page with the state of the store, the secret, Turnstile and email, with steps for each host: @../../../../.claude/skills/forms/SKILL.md
